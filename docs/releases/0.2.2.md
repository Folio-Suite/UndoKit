# UndoKit 0.2.2 — beta maintenance candidate

Planned framework version/build: **0.2.2 / 4**. This is a release-preparation
record for [PR #74](https://github.com/Folio-Suite/UndoKit/pull/74), not a published
release or an approval of candidate bytes. The preceding published release is
[0.2.1](https://github.com/Folio-Suite/UndoKit/releases/tag/0.2.1).

## Fixed

Hosts could retain presentation metadata and resolve action names through the
advanced reading API, but could not connect those names to the ordinary
History Session's native UndoManager. Native menus therefore lacked localized
per-group names through the supported attachment route.

Install `session.setNativeActionNameResolver(_:)` to decode host-owned metadata
and return a localized action name. Names refresh with native availability,
including name-only changes, and follow Undo, Redo, reconciliation and reopening.
Install the resolver again after reopening or when the host's language changes.
Missing metadata, nil results and resolver errors use generic native labels.

Focused local and live text retains its native names and empty-stack isolation.
Native callbacks still initiate asynchronous semantic work; use the session's
awaitable operations when completion must be observed. See the
[first-group guide](../../UndoKit/UndoKit.docc/FirstUndoGroup.md) and
[presentation contract](../history-reconstruction.md#presentation).

Native Xcode project configurations also inherit the central framework build
number, correcting a stale project-level build `1` override in the developer
harness. The archive producer already supplies explicit release version/build;
this does not change the identity of previously published binary assets.

This corrects [#73](https://github.com/Folio-Suite/UndoKit/issues/73). Framework
runtime code and the public API change from 0.2.1; this is not a runner-only patch.
The persistence schema, model, privacy manifest and resolved dependencies are
unchanged. Durable Notes now emits illustrative opaque presentation metadata.

## Source validation

The action-name implementation at `053221e9a2cf1b7b1dadefe5b4be84a162e13826`
has the following measured evidence from Xcode 27.1 / Swift 6.4 on macOS 27.0.1:

- Full package tests: Debug 167, Release 155, one skip each, zero failures.
- Three action-name regressions cover native names/menu titles, typed groups,
  Undo/Redo, reopen, resolver replacement/removal/error fallback, busy/unresolved
  states, reconciliation and clearing.
- Eighteen sample host tests pass. Installed AppKit checks pass when launched
  through LaunchServices, including durable labels, live names and empty-local
  isolation. Direct executable launches failed initial responder routing before
  reaching the new assertions; no successful direct-launch claim is made.
- Independent macOS source-package and native-framework consumers pass in Debug
  and Release, including universal native builds and installed resource checks.
- UIKit builds and passes the new name assertions on iPadOS 26.5. Its full check
  later times out during a restored-rejection background transition. Broader
  simulator consumer checks refuse validation while other simulators are booted.
  These are incomplete runtime qualifications, not complete suite passes.

The [documentation hygiene record](../maintenance/2026-10-19-022-documentation.md)
records the release documentation inventory, final checks and remaining limits.
The 0.2.1 API documentation does not cover this new resolver; publish a new 0.2.2
DocC snapshot with the candidate rather than treating older guidance as complete.
